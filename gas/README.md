# 把訂單收進 Google 試算表

網站是靜態頁，不能保管金鑰。訂單改由這份 Apps Script 收到後，追加到試算表。試算表就是第一版後台，不另做管理密碼頁。

LINE Pay 先不要接。`doPost` 若收到 `action: "linepay"` 會回「尚未開通」。Channel ID 與 Channel Secret 之後放在 Apps Script 的指令碼屬性，不要寫進 `config.js` 或這個檔案。

## 部署

1. 打開 [Google 試算表](https://sheets.google.com)，新增一個空白試算表。名稱可取「YB 團購訂單」。
2. 選單 **檔案 → 設定**，時區選 **(GMT+08:00) 台北**。
3. 選單 **擴充功能 → Apps Script**。
4. 把預設的 `Code.gs` 內容全部換成這個資料夾的 [`Code.gs`](Code.gs)，然後儲存。
5. 右上角 **部署 → 新增部署**。
6. 類型選 **網頁應用程式**。
7. 說明可填「團購訂單」。
8. **執行身分**選 **我**。
9. **誰可以存取**選 **任何人**。這是讓公開網頁能把訂單送進來。試算表本身不要設成「知道連結的人可編輯」。
10. 按 **部署**。第一次會要求授權，用試算表擁有者的 Google 帳號允許。
11. 複製網址，長得像 `https://script.google.com/macros/s/xxxxxxxx/exec`。
12. 貼進網站 [`config.js`](../config.js) 的 `FORM_ENDPOINT`，推上 `main`。
13. 用瀏覽器打開那個 `/exec` 網址，應看到 `{"ok":true,"service":"yb-groupbuy-orders"}`。
14. 再到團購頁下一筆測試單，回到試算表看有沒有新的一列。工作表名稱是「訂單」。

改了指令碼之後，要 **部署 → 管理部署 → 鉛筆 → 版本選新版本 → 部署**。只儲存不會更新已經公開的網址。

## 試算表欄位

時間、訂單編號、姓名、手機、Email、取貨方式、地址門市、備註、品項明細、合計、付款方式（`transfer` 或 `linepay`）、匯款後五碼、付款狀態、原始 JSON。

付款狀態由程式寫入：

| 情況 | 狀態 |
| --- | --- |
| 選匯款、還沒填後五碼 | 待付款 |
| 選匯款、有 5 碼 | 已匯款待確認 |
| 選 LINE Pay | LINE Pay待開通 |

對過帳、確定入帳之後，在試算表把該列的付款狀態改成 **已付款**。網站不會自己改這一格。

## 網站上看不到寫入結果

瀏覽器對 `script.google.com` 用 `no-cors` 送出，避免預檢被擋住，所以頁面無法讀回試算表的回應。買家仍會看到自己這筆的訂單編號。主辦要打開試算表確認有這一列。
